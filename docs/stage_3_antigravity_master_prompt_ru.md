# Мастер-задание для coding agent: этап 3 дипломного проекта

## Роль coding agent

Ты выступаешь как senior Python/FastAPI developer и frontend developer. Создавай рабочий, понятный и проверяемый код. Автор дипломного проекта должен понимать и уметь объяснить каждое решение на защите, поэтому избегай чрезмерно сложной архитектуры и скрытой магии.

Не имитируй работу AI, RAG, API или базы знаний. Если интеграция ещё не реализована, показывай честное состояние «подготавливается».

## 1. Контекст проекта

Название проекта:

**«Персональный сайт с AI-ассистентом для представления профессиональных компетенций»**.

Автор:

**Андрис Янчевскис**.

Проект создаётся как дипломная работа по разработке AI-агентов. Первая версия сайта и весь пользовательский интерфейс должны быть на русском языке.

Главная идея: посетитель описывает вакансию, проект или профессиональное требование. В будущей версии AI-ассистент должен находить подтверждённые сведения об опыте Андриса, сопоставлять их с запросом и предлагать уместный следующий шаг. Если подтверждённых данных недостаточно, ассистент обязан прямо сообщать об ограничении, а не придумывать факты.

## 2. Текущая цель MVP

Создать **полностью спроектированный, визуально законченный и адаптивный персональный сайт**, даже если некоторые сведения ещё отсутствуют или ожидают подтверждения.

В рамках текущей итерации необходимо:

- создать полноценную структуру сайта;
- реализовать профессиональный дизайн всех основных разделов;
- заполнить сайт только подтверждёнными сведениями;
- предусмотреть нейтральные состояния для отсутствующей информации;
- создать законченный интерфейс будущего AI-ассистента;
- подготовить архитектуру проекта к последующему подключению RAG и LLM;
- реализовать FastAPI-приложение, конфигурацию и автоматические тесты.

В текущей итерации **не реализовывать** настоящие обращения к LLM, эмбеддинги, векторный поиск и генерацию ответов.

## 3. Будущая архитектура AI-ассистента

Архитектура должна быть учтена при организации проекта, но её AI-компоненты пока не реализуются:

1. Пользователь вводит вопрос.
2. Первое обращение к LLM определяет намерение пользователя и формирует поисковый запрос.
3. RAG выполняет поиск по внешней векторной базе знаний.
4. Второе обращение к LLM создаёт ответ только на основании найденных подтверждённых фрагментов.
5. Интерфейс показывает ответ и ссылки на релевантные источники или проекты.
6. При отсутствии достаточного контекста ассистент выдаёт корректный отказ.

Будущая реализация должна удовлетворять требованиям диплома:

- не менее двух последовательных обращений к LLM с разными самостоятельно разработанными промптами;
- внешняя RAG-база знаний;
- чанкинг документов;
- создание эмбеддингов;
- векторное хранилище;
- поиск релевантных фрагментов;
- production-интеграция через пользовательский веб-интерфейс;
- экспериментальное сравнение параметров и документирование результатов.

## 7. Конфигурация через Pydantic

Реализуй `app/core/config.py` с использованием `pydantic-settings`, `BaseSettings` и современного синтаксиса Pydantic v2.

Настройки:

- `app_name: str`;
- `app_env: str`;
- `openai_api_key: str | None`;
- `llm_model: str`;
- `embedding_model: str`;
- `vector_db_path: str`.

Настройки должны считываться из `.env`. Используй `SettingsConfigDict`. Экземпляр настроек должен возвращаться функцией `get_settings()`, защищённой `@lru_cache`.

Создай `.env.example`:

```dotenv
APP_NAME=Персональный AI-ассистент Андриса Янчевскиса
APP_ENV=development
OPENAI_API_KEY=
LLM_MODEL=
EMBEDDING_MODEL=
VECTOR_DB_PATH=./data/qdrant
```

Пустые значения AI-настроек допустимы в текущей итерации. Приложение и главная страница должны запускаться без API-ключа.
